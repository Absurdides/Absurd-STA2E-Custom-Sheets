# STA 2E Unified Character Console - Project Notes

## Mission
A Star Trek Adventures 2nd Edition character sheet web page with three uses:
1. Print as a blank character sheet.
2. Print as a customizable, fillable character form.
3. Use interactively as live character tracking during play.
Changes must not break any of the three (screen layout, print layout, save/load).

Paste or attach this at the start of a new chat, together with the current `index.html`, `style.css` and `console.js`.

## Who / how to work with me
- User is on long-term disability with limited usage. Keep replies SHORT, no pleasantries, minimal explanation.
- Edit the existing files (`index.html`, `style.css`, `console.js`) with targeted edits (str_replace / small scripts). Do NOT rewrite whole files or re-read the whole file; search for the section you need.
- After each change: check JS syntax (node), then present the file (present_files).
- Verify layout and print before delivering when possible: some chats have headless Chromium in the sandbox (`from playwright.sync_api import sync_playwright`, browsers in `/opt/pw-browsers`). Load `file:///.../index.html` with `fonts/` beside it, stub `window.print`, click the button, then `page.emulate_media(media='print')` + `page.pdf(...)` and `pdftoppm` to view pages. Say what was and wasn't verified; if no browser is available, ask the user for screenshots and never claim layout was visually verified.
- Batch changes. Ask at most one question when truly ambiguous.
- Copyright: copy rulebook / fan-site rules text into files or replies where possible. Otherwise, names and structure only.
- Runs locally from a folder on Windows (file://) or online via GitHub Pages. Browsers block fetch of .json, so data lists are `.js` files loaded with <script src>.

- RULES-TEXT POLICY: every rule stated in the sheet (Page 6, all ⓘ popovers) must be verifiable in the Core Rulebook (primary source, highest priority; it wins if sources differ), the Quickstart Guide v1.1 (`.md`) or `spends.js`. Do not add rules from memory or fan sources. Surge of Activity and Make It So are 1st edition and must not be reintroduced. Unverifiable rules were removed (Revival, Knockdown/Stun/Vicious qualities, Opportunity Cost rules, extended task formulas). EXEMPT: `toolkit.html` (separate reference, core-book text kept as the owner supplied it).
- Docs rule: when a feature's behaviour changes, update `manual.html` (the only copy of the user manual). `README.md` is a short static pointer and is not edited.

## Storage, Slot Caps & Roster/Fleet Files
Storage, slot caps and Roster & Fleet files (built). Measured 2026-10-18: ship with image 148 KB; 5 full characters + 1 ship = 895 KB Backup All, about 150 KB per full character; about 25 full characters + 8 ships fit in the roughly 5 MB localStorage limit.
  1. Storage meter `#storage-meter` (`.storage-meter`, Session row, left of the divider before Clear Form): `storageUsed()` sums key + value lengths of all `sta2e*` keys vs `STORE_LIMIT` = 5,000,000 (estimate; KB in tooltip). `updateStorageMeter()` runs in slot `go()` and when the autosave dot turns saved (so after autosave, import, restore, delete). Amber at 80% (one-time alert per session), red at 95%. Clicking opens the Storage Details modal (`#storage-modal`, `.storage-box`) with a memory breakdown and a safety-backed "Remove Unlinked Data" button.
  2. `storageFull()` (>= 90%) refuses `+ New`, `Copy` (via `full()`), the New Slot choice on Import Crew / Import Ship, `offerShip()` and Restore All "Add to My Slots". Undo of a slot delete is not blocked.
  3. Per-type caps: `MAX_CREW = 50`, `MAX_SHIPS = 8`, passed as `max` to `makeSlots()` (also used by `importAll()`, `restore()`, `canAdd()`).
  4. Export Crew asks Include Ship / Character Only / Cancel: `saveFile(prefix, withShip)`; Clear Form backup is character-only. Importing a file with a ship still offers `offerShip()`. Format name stays `sta2e-unified-v3`.
  5. Restore All (`sta2e-backup-v1`, described as the Roster & Fleet master file in README, manual and tooltips; buttons not renamed): choice Replace Everything (old behaviour) or Add to My Slots (`addAll()` in `makeSlots()`: new ids `prefix + Date.now() + '_' + n`, fills free slots only, alert lists entries that did not fit).
  6. Image limits: see Save / load > Images (box fit, WebP, open-time migration).
  7. Housekeeping done: manual docs, `?v=` strings (style/console 3.3), `CACHE` = `sta2e-console-v7`.

Max 1990 chars per part (plus 8 fence chars), packed at block boundaries, a header is kept with its next block, long text split by `splitLong()` (line break, sentence, word, hard). Popup `#discord-modal`: one textarea + Copy per part (clipboard API on https, `execCommand('copy')` fallback for file://). Esc closes it.
- Markdown (shared converter, console.js "Markdown <-> blocks"): `mdToBlocks()` (markdown to block list, fed to `importBlocks()`), `blocksToMd(blocks, compact)` / `blockMd()` / `mdSep()` (blocks to markdown), `mdInline(s, html)` (inline `**`/`*`/`_` to `<b>`/`<i>` or plain text; backslash escapes survive via private-use placeholders; no regex lookbehind, for older Safari), `htmlToMd()` (paragraph HTML to markdown), `escMd()` / `escHtml()`. Import Markdown (`#md-import`, bottom bar) opens `#md-modal` (paste box + .md/.txt picker) then reuses the Import Sections dialog. Mapping: `#`-`######` headings become header bars (all `blue`; recolour with the colour cycle); blank-line paragraphs become Paragraph blocks (soft-wrapped lines joined with a space; two trailing spaces or `\` = line break); a single-line paragraph `**LABEL:** text` becomes a Detail Row (`cap-tan`); list lines kept as text lines (`-` / `1.` markers, `*` / `+` normalised to `-`); tables flattened to `a | b`; code fences, links, images, strikethrough flattened to plain text; `---` dividers dropped (overflow flows into new sections via `spillOverflow()`).
- Discord popup (`showDiscord(data)`): Format toggle (Code block = `discordParts()`; Markdown = `mdDiscordParts()`, compact markdown in parts of at most 1950 characters; last choice kept in localStorage `sta2e_discord_fmt`) and Download .md (`blocksToMd(data, false)`, header bar `## TITLE`, paragraph with `**`/`*`, detail row `**LABEL:** text`, ruled lines skipped). Discord findings (screenshot tests): an attached `.md` shows one compact card with a collapsed rendered preview (heading, bold, italic), expand chevron, `<>` source toggle and fullscreen; an attached `.txt` shows the same lines as raw text; spoilers `||...||` span lines and render markdown inside but keep the full text height when hidden, so they were rejected; Discord has no collapse for pasted messages. Round trip: exported `.md` re-imports via Import Markdown, but colours are lost (markdown cannot carry them) and a detail row comes back as a Detail Row only when it is a single line. `addBlock()` now always sets paragraph text as HTML (Reset Mission and legacy restore escape their plain text first), which fixed `&` showing as `&amp;` after reload.

## Task Roller (Page 1 and Page 5, Play Mode only)
- Built in console.js "Task Roller" block (state `R`, panel `#roll-panel`, `.no-print`, never saved). Tap a Page 1 Attribute / Department capsule (`.single-stat-capsule`, not the `±` box) to select (`.roll-sel`); tap again to deselect; nothing selected closes it. Clear, x and Esc call `clearRoll()`; leaving Play Mode and slot switches also clear it.
- Ship mode (Phase 2): `R.mode` is 'char' or 'ship'. Tapping a Page 5 `.ship-system-card` / `.ship-dept-capsule` (not the `±` box or the breach column) selects `ship_sys_*` / `ship_dept_*`; TN = System + Department + both `±` mods. Default 1d20, no Focus (critical = roll of 1), Difficulty and Momentum as Page 1 (the pool is the Page 1 `combat_momentum_*` pips). Switching pages and picking a stat in the other mode clears the roller first. Ship System and Department scores are read-only in Play Mode (added to `lockNames`). Panel floats over `.ship-middle-tactical-row`, leaving Systems and Departments visible.
- Dice tray (Phase 3): `#btn-dice` (Tools row, `.play-only`, green `.btn-dice`) toggles `R.mode = 'tray'`: no stats, TN input (`R.tn`, default 10; blank falls back to 10), dice 1-5 (default 2), Difficulty default 1 (can step down to none, shown as a dash), no Momentum buying; floats fixed at the top right below the top utility menu bar (docks under 700px). Scored like any other roll.
- Technical Log: after a roll a `Log` button opens a persistent `.rp-log` form: required Task, Focus select (`R.lfocus`, default None; pre-selects the roller's Focus), optional Directive text input, No stardate box. `rLogText(task, focusText, dirText)` builds two lines: `Task (Focus: X, Directive: Y)` then `[TN n, Diff d] ND20, S Successes (Pass) · Spent 1 Determination`. Label is `Stardate N` from the Stardate bar, or `Stardate ?` when the box is ticked or the bar is still Jan 1, 2376 (`sdIsDefault()`). `rLogRow()` temporarily shows Page 4, appends a Tan detail row to the last Tech section, and if it overflows moves the row into a new Tech section ("Technical Log (cont.)"; max `MAX_TECH` = 6). Never automatic. Quick Note is separate (still uses the bar value).
- Determination Spends in Roller: In character mode, `★ Perfect Opp` locks one die to 1 (Critical) pre-roll and deducts 1 Determination upon Roll. Post-roll, tapping dice chips toggles a blue outline (`.reroll-sel`) for selective re-rolling via `Moment of Insp (N dice · 1 Det)`, which unchecks 1 Determination pip and recalculates successes.
- Tech section (Page 4): views carry `data-tech="1"` (always the last views; pagination shows `TECH`, `TECH 2`...; tan button, orange when active). `ensureTech('p4')` runs in `defaultDoc` and `restore`: creates one (header bar "Technical Log") if missing, marks legacy sections whose first header starts with "Technical Log", and moves Tech views to the end. `addSection(id, tech, force)` inserts normal sections before the first Tech view and calls `renumber()`; normal sections are capped at `MAX_SECTIONS` (8) excluding Tech. `collect()` saves `techTabs`. `removeLastSection`, `moveBlock` (no crossing into/out of Tech), `spillOverflow` (never spills into Tech), Quick Note / Reset Mission (`logTab()` = last normal section when Tech is active) and Print (PDF) (skips a Tech section that has only its header) all respect it.
- Placement: `placeRoll()` floats the panel over the right column of `.tactical-stats-container` (Species Ability + Values), scaled by page width / 768 so Fit zoom works; under 700px it docks to the bottom (`.rp-dock`).
- TN = Attribute + Department + both `±` mods (blank = 0). Critical: Focus on = roll <= Department (incl. its mod), Focus off = roll 1. Roll of 20 = complication. Dice 1-5 (default 2), Difficulty 0-5 (default 1), PASS = successes >= Difficulty, Momentum = surplus.
- Momentum buying: `BUY_COST` = [0,1,3,6] for +0/+1/+2/+3 dice (total max 5), limited by checked `combat_momentum_1..6`; deducted on Roll (highest pips unchecked, `markDirty()`), refund by re-ticking. Optional Add to pool button (cap 6). Not part of Undo.
- All pip tracks (`combat_momentum_`, `stress_`, `ship_shield_`, `determination_`, `ext_task_work_`, `ext_task_bt_`, `ship_sys_<sys>_b`) behave as scales via `trackScale()` / `TRACK_RE` (change handler, Edit and Play Mode): tap N fills 1..N; tapping the top filled pip removes one; tapping a lower filled pip sets the track to it. The Focus picker is a full-width row below the dice controls (`.rp-frow`) so long Focus text cannot push the layout; grid columns use `minmax(0,1fr)`.
- Rolls use `crypto.getRandomValues` (rejection sampled); 800 ms `??` shuffle, skipped with prefers-reduced-motion. Focus picker lists the non-empty `ledger_focus_1..6`. Determination spends deliberately not included (see ROADMAP.md).

## Session Management & Mobile / Tablet Play
- "Mode: Edit 🔓 / Play 🔒": Toggles tablet-friendly read-only lock on static bio, core stats, and talents to prevent accidental touches. Unlocks live tracking, `±` modifiers, Value challenge toggles, and 2E rules popovers.
- "Reset Mission": Archives `ledger_mission_directives` to Page 4 under an Orange header ("Mission Debrief: Stardate XXXXX") + paragraph; clears Stress track; clears Tactical Momentum pips; clears Extended Task work/breakthrough pips and Magnitude; resets `±` stat modifiers; clears mission requisitions; restores baseline equipment.
- "PADD ⛶": Toggles native browser fullscreen mode to hide tablet/phone browser chrome during live table play; also requests a screen wake lock (https only).
- "Reset Ship": clears all Shield and Breach boxes on the active ship (stats kept). "Reset Mission" never touches the ship.
- "Quick Note" (Play Mode): prompts for text, appends a Tan detail row "Stardate N" to Page 4 Logs.
- Dark Play Mode: screen-only CSS filter inversion of `.printable-page-area` when `Theme: Dark` (Edit or Play Mode; unset preference = dark in Play, light in Edit) (preference in localStorage `sta2e_dark_play`); images/popovers counter-inverted; never affects print.
- "Fit ↔": Scales sheet to match tablet screen width for seamless edge-to-edge reading; unzooms cleanly for print.
- Larger Touch Targets (Play Mode): Scoped to `@media (pointer: coarse)` on touchscreens to expand invisible hit areas on dense checkbox tracks (Stress, Ship Shields, Breaches, Breakthroughs) for effortless tapping without shifting layout or affecting mouse precision on PC/laptop.
- Live Autosave Indicator: Pulsing dot beside the Session label and File ID reflects storage sync status (Green = Saved, Amber = Pending). Clicking dot forces instant save.

## Save / load
- Export Crew (`#utility-btn-save`) -> one JSON named from FILE ID (`_bundle: sta2e-unified-v3`): all named fields + `docs: {p3:{sections,blocks[]}, p4:{...}}` + `base_equipment` + `challenged_values` + portrait.
- Slots (localStorage, up to 50 characters + up to 8 ships, independent): index `sta2e_storage_slots_index` / data `sta2e_slot_data_<id>` / active `sta2e_active_slot`; ships `sta2e_ship_slots_index` / `sta2e_ship_data_<id>` / `sta2e_active_ship`. Character slots exclude `ship_*` fields; they store `_play_mode` (Edit/Play restored per slot). Managed by `makeSlots()` in console.js; `applyData(d, 'char'|'ship')`.
- Autosave: debounced 500 ms into the active character slot and active ship slot; dot green = saved to browser memory. Names follow `bio_name` / `ship_name` unless renamed. Quota fallback drops images and warns once. Legacy `sta2e-autosave` migrated once.
- Load File / Import Ship ask: New Slot / Replace Current / Cancel. Character file with a ship offers a new ship slot. Clear Form clears the active character only (downloads backup first). Export Crew asks whether to bundle the active ship.
- Keep field `name` attributes stable; renaming breaks old saves.
- Undo: one step, in memory only (lost on reload). Snapshots taken before Reset Mission, Reset Ship, Clear Form, Load/Import Replace, Import Sections, Delete Selected, and slot Delete (restores deleted slot).
- Backup All / Restore All: one JSON (`_bundle: sta2e-backup-v1`) with all character + ship slots. Restore offers Replace Everything (after auto-downloading a backup of the current state) or Add to My Slots.
- Images: `shrinkImage(file, box, cb)` / `shrinkSrc(src, box, cb, onlyIfLarger)` fit uploads inside a box (never upscaled): `IMG_PORTRAIT` 320x220 q0.6, `IMG_SHIP` 1434x192 q0.7 (portrait about 2.5x the 128x86 box; ship exactly 2x the 717x96 box, and ship images are almost always height-limited). White background, `encodeImage()` tries WebP and falls back to JPEG when the browser returns another type (Safari). Never stores something bigger than the original. No small-file bypass. Already-stored images are migrated lazily: `applyData()` re-encodes a stored portrait / ship image only if it exceeds the box by more than about 15% (`s <= 0.85`), guarded by `portraitTok` / `shipTok` (bumped by `setPortrait` / `setShipGraphic`) so a slot switch cannot receive another slot's image, then `markDirty()`. Slots never opened (and Restore All data) shrink the first time they are opened.
- Print hides UI-only hints on every printed sheet (screen placeholders in inputs/textareas, the portrait and ship-graphic upload text) via `@media print` rules; Print Blank relies on the same rules. Old ship files with the default id `NCC-80106-[PHOBOS_DEFAULT]` are converted to `SHIP_DEFAULT` on load.
